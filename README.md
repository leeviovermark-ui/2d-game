# WORLDFORGE

An original 2D social sandbox built in **Godot 4.6.3**, with a **Python 3.12+ authoritative WebSocket server** and **SQLite WAL persistence**. All pixel art and interaction sounds are generated by this project. The bundled DejaVu Sans font has its license in `assets/fonts/LICENSE.txt`.

This is a playable development slice for a small multiplayer server. Two clients connected to one server see each other and the same terrain changes. The server owns inventory, building, crafting, trading, and administrator permissions.

## Play on Windows

1. Install **Python 3.12 or newer**, then extract the complete `WORLDFORGE-playable.zip`.
2. Open the extracted **WORLDFORGE** folder and double-click **Play-WORLDFORGE.bat**. The launcher installs the Python dependency when needed and opens your browser after the server is ready.
3. Create an explorer account, or sign in to your existing account. Keep the launcher window open while playing. Press **Ctrl+C** in that window to save and stop.

If the browser does not open automatically, visit **http://127.0.0.1:8765** in Chrome or Edge. The game also starts from PowerShell inside the WORLDFORGE folder with `py scripts/play.py`. A second browser tab with another account joins the same server.

**Updating an older download:** stop its server first. Copy your old `data` folder into the newly extracted `WORLDFORGE` folder before starting the new launcher. That folder contains your accounts, inventory, and worlds. The upgrade adds database tables without deleting your existing progress.

For macOS or Linux, run `python3 scripts/play.py` in the extracted folder. The playable ZIP includes the browser build, so these launchers do not require Godot.

## Run

```sh
bash scripts/setup.sh
# Terminal 1: authority + browser-client HTTP server
bash scripts/serve.sh
# Terminal 2: native Godot client
bash scripts/godot.sh
```

Open `project.godot` in Godot for editing. Create an explorer account in the client, or sign in to an existing account. A second client uses a different account and the same server address. Accounts receive one small starter kit exactly once. Creating a second connection with the same account replaces the first connection.

**Browser client:** the cloud workspace includes verified Web export templates and `build/web`. `bash scripts/export_web.sh` refreshes the browser build. For a fresh machine, run `python3 scripts/install_templates.py` first; it verifies the official bundle's SHA512 checksum. The default local HTTP endpoint is `http://127.0.0.1:8765`; the client discovers its WebSocket endpoint from the page origin. Native clients default to `ws://127.0.0.1:8765`.

For remote development, `bash scripts/serve.sh --host 0.0.0.0` binds the server to all interfaces. Put it behind an HTTPS/WSS reverse proxy before transmitting passwords over a network. Credentials are scrypt-hashed; reconnect sessions expire after 30 days and are stored as hashes on the server. A local client stores only its bearer session token, never the password.

## Administration

Press **Enter**, type **`/addomen`**, and press **Enter** again to open the admin menu. It includes a searchable block/item catalogue, item grants to yourself or another explorer, an account directory with online/banned/muted filters, kicks, permanent bans and unbans, timed chat mutes and unmutes, and travel to an existing world's safe spawn. Ban and kick actions require confirmation. Every action is checked and saved by the server.

On a local server using the default `127.0.0.1` address, the **oldest existing account** becomes administrator the first time this upgrade starts. With a new database, the **first account created** becomes administrator. Other accounts remain regular explorers. Administrators cannot kick, ban, or mute themselves or another administrator through this menu.

To choose an existing administrator explicitly, start with `py scripts/play.py --admin YourExplorerName` on Windows, or `python -m server.main --admin YourExplorerName` when running the authority directly. Repeat `--admin` for additional names. Servers listening publicly do not automatically appoint a first-account administrator; create your intended account locally before starting publicly with `--admin`. Roles and moderation remain saved across restarts. Typing the command as a regular explorer does not grant access.

## Play

| Control | Action |
| --- | --- |
| A / D or arrow keys | Move |
| Space / W / up | Jump; hold for more height, release for a shorter hop |
| Hold left mouse | Mine target within five tiles |
| Right mouse | Place selected block; plant seeds |
| E | Harvest / open storage / use station under cursor |
| 1–9 / 0 / mouse wheel | Select hotbar |
| I | Inventory; drag stacks, right-click to split |
| C | Crafting, ingredients and station requirements |
| M | Visit or create named worlds |
| P | Other explorers; trade or block chat |
| Enter | World chat |
| H / J / Esc | Field guide / notes / close panel |

Gather cedar and fiber from trees, mine stone with your cedar pick, and craft a stone pick near the shelter workbench. A stone pick opens iron veins; iron tools reach lumen crystals. Place seeds on earth and harvest after **90 seconds**, including time offline. Storage transfers whole stacks atomically. Create a world, then place a **World Core** to claim it. Owners can permit guests or name builders. NEXUS stays an unclaimed shared refuge.

Movement runs at **60 simulation steps per second**. Your explorer responds immediately to local input, then reconciles with the server; other explorers use buffered snapshot interpolation. Jumps accept a short grace period after leaving an edge and remember a press shortly before landing. Releasing the jump key early makes a shorter hop.

The expanded workshop contains **48 items and 33 recipes**. Build with mossy stone, midnight slate, sandstone, frost marble, terracotta, reinforced glass, and rosewood/azure/sage timber. Decorate with iron-bound beams, hedges, planters, chairs, tables, bookshelves, tapestries, and rugs. Iron lanterns and lumen lamps light underground builds. Craft a **lumen pickaxe** at a workbench from four crystals, six iron ingots, and three cedar logs for faster mining. Furniture is decorative; storage chests and crafting stations retain their existing interactions.

Trading requires two nearby explorers: request → accept → edit exact item offers → both lock → both confirm. Editing an offer clears every lock and confirmation. Inventory changes and pickups pause during a trade. Closing the trade, travelling, disconnecting, or moving out of range cancels safely. Both inventories and the transaction audit entry commit together.

## Architecture and current limits

See [docs/architecture.md](docs/architecture.md). `shared/definitions.json` is the single stable-ID registry. Persistent state is in ignored `data/worldforge.sqlite3`; back up the database with SQLite's backup API. Generated `.godot`, `.tools`, `.venv`, and `build` directories are local setup outputs.

The slice uses bounded **144 × 56** worlds, one full world snapshot on entry and subsequent deltas, world-scoped interest, and inactive-world unloading. SQLite mutations run synchronously in one authority process. Database schema 2 adds administrator roles and moderation to existing saves. Large-world chunks, distributed simulation, a load-tested population limit, account recovery, and a broader moderation workflow remain future work.

Shops, currencies/marketplace, automation, combat/bosses, clothing/equipment slots, friends/private messages/guilds, and player logic objects are **not implemented**. They have no pretend buttons. This milestone establishes the resource/build/farm/craft/store/social/trade loop before expanding those systems.
