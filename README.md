# WORLDFORGE

An original 2D multiplayer sandbox built in **Godot 4.6.3**, with a **Python 3.12+ authoritative WebSocket server** and **SQLite WAL persistence**. Explore, build, garden, run a workshop, and make a home with friends. Pixel textures and interaction sounds are generated by this project; bundled runtime and font notices are in `assets/licenses/Godot-4.6.3-notices.txt` and `assets/fonts/LICENSE.txt`.

**Stage 3.0** fixes the shared-server hosting flow: dedicated same-Wi-Fi Host and Join launchers, an optional temporary internet host, a persistent HTTPS/WSS deployment, clearer server selection, and safer public-server authentication. It retains Stage 2's starting menu, account recovery, friends, live world catalogue, larger worlds, and **177 items with 150 recipes**. The next expansion, **The Living Loom**, is designed in [docs/stage3-plan.md](docs/stage3-plan.md): visible circuits, Echo puzzles, habitats, workshops, and settlement celebrations. Those expansion mechanics are planned and are not included in this hosting release.

## Play on Windows

1. Install **Python 3.12 or newer**, then extract the complete `WORLDFORGE-playable.zip`.
2. Open the extracted **WORLDFORGE** folder and double-click **Play-WORLDFORGE.bat**. The launcher prepares its Python dependency, starts the server, and opens your browser when ready.
3. Select **Play WORLDFORGE**, create an explorer account or sign in, and save the recovery code shown for a new account. Keep the launcher window open; press **Ctrl+C** there to save and stop.

If the browser does not open, visit **http://127.0.0.1:8765** in Chrome or Edge. You can also start from PowerShell inside the WORLDFORGE folder with `py scripts/play.py`. A second browser tab with another account joins the same server. The ZIP includes the browser game, so playing does not require Godot.

**Update without losing progress:** stop the old server first. Extract the new ZIP into a new folder, then copy your old **`data` folder** into its **WORLDFORGE** folder before starting the launcher. That folder contains accounts, inventories, and worlds. Existing worlds retain their original terrain and dimensions; newly created Stage 2 worlds use the larger generation. Saved browser sign-in can continue when the server address stays the same.

On macOS or Linux, run `python3 scripts/play.py` in the extracted folder.

## Play with a friend on the same Wi-Fi

1. Choose **one computer to host**. Stop its existing game server with **Ctrl+C**, then double-click **Host-WORLDFORGE-LAN.bat** in the extracted folder.
2. If Windows asks about Python, allow it on your **private network**. The host window displays an address such as `http://192.168.1.25:8765`.
3. Each friend extracts the same game download, double-clicks **Join-WORLDFORGE-LAN.bat**, and pastes the host's displayed address when asked. This opens a local browser client connected to the shared host. Everyone uses a **separate explorer account**, and the host keeps its server window open.

`127.0.0.1` refers to the computer using it. Starting **Play-WORLDFORGE.bat** on every computer starts separate games. The **Join** launcher serves only a local copy of the client; accounts, worlds, chat, and building come from the selected shared host. It creates no separate game database. Godot requires a secure browser context, which localhost provides; opening the game directly at an HTTP Wi-Fi address fails that requirement. The Join launcher avoids certificate installation and browser security overrides.

If a friend cannot connect, check that the host window is still running, both devices use the same private network, and Windows Firewall allows Python's TCP port **8765**. Guest Wi-Fi or wireless client isolation can prevent devices from reaching each other. Use the host's active Wi-Fi IPv4 address from `ipconfig` if several addresses are listed. Linux/macOS hosting uses `python3 scripts/play.py --host 0.0.0.0`; friends run `python3 scripts/join_lan.py --server http://HOST_LAN_IP:8765`. Keep the Join window open while playing.

## Play over the internet

**Host-WORLDFORGE-Online.bat** starts a public-mode authority and an optional Cloudflare quick tunnel. The first run downloads the pinned official tunnel application and checks its SHA256. Once the public address responds correctly, the launcher prints a shared **HTTPS** link. Everyone opens that link and uses a separate account. The host keeps the window open; **Ctrl+C** saves and closes it. Linux x86-64 uses `python3 scripts/host_online.py`.

Quick tunnels provide temporary test sessions: the address changes on restart, browser continuation is specific to that address, and Cloudflare supplies no uptime guarantee. Accounts and worlds remain in the host's `data` folder. If the service is blocked or unavailable, the launcher reports the failure; a local address does not become an internet invitation.

For a stable address and a server that stays online when your PC is off, [docs/hosting.md](docs/hosting.md) provides a persistent Docker/Caddy deployment with HTTPS, WSS, durable saves, and backups. It requires a server and a domain pointing to it. This download does not include a managed public server. See [docs/validation.md](docs/validation.md) for the precise tests and remaining external-hosting verification.

## Your account

The starting menu supports account creation, sign-in, saved-session continuation, and password recovery. Names use **3–20 letters, numbers, or underscores**, starting with a letter. Passwords use **8–128 characters**; new passwords require confirmation. You can show the password while typing and choose whether this device remembers your session.

A new account receives one starter kit and a **one-time recovery code**. Copy or download the code and keep it privately: it can reset the account password on this server. Recovery does not use email. A code expires after one year; using it replaces it with a new code and revokes all saved sessions. Existing accounts can generate a code from **Settings → Account & saved sessions** after confirming their password.

If the connection drops just after account creation or password recovery, sign in with the password you chose. The account may already be saved even if its recovery notice did not reach you. Once signed in, generate and save a new recovery code from account settings.

Account settings also let you change your password, replace a recovery code, sign out other saved sessions, or sign out and forget this device. Changing a password revokes other saved sessions while keeping the current one. The server stores scrypt password hashes and session/recovery hashes; the client remembers a bearer session token rather than your password. Sessions expire after 30 days. A second connection with the same account replaces the first.

Browser continuation uses the browser's local storage. If storage is unavailable, the game explains that it cannot remember this device; your account and progress still remain on the server. Upgrading migrates older remembered sessions and clears their old cached credentials. Signing out revokes the current server session and forgets the browser credential.

Accounts and progress belong to the server you connect to. Another server has a separate account database. Network hosting should use an HTTPS/WSS reverse proxy so passwords and session tokens travel over an encrypted connection.

## Controls

| Control | Action |
| --- | --- |
| A / D or arrow keys | Move |
| Shift while moving | Sprint using energy |
| Space / W / up | Jump; hold for more height, release for a shorter hop |
| Hold left mouse | Mine a target within five tiles |
| Right mouse | Place the selected block or plant seeds |
| E | Harvest, open storage or a workshop, fish, or use a portal under the cursor |
| F | Eat food selected on the hotbar |
| G | Cast a selected fishing rod at nearby water |
| 1–9 / 0 / mouse wheel | Select hotbar slot |
| I | Inventory; drag stacks, right-click to split |
| C | Crafting, ingredients, and station requirements |
| M | World catalogue, favorites, and world creation |
| P | Friends, private messages, invitations, and nearby explorers |
| L | Explorer journal, wardrobe, and emotes |
| K | World minimap |
| Enter | World chat |
| H / J / Esc | Field guide / notes / close a panel |

Movement uses **60 simulation steps per second**, immediate local prediction, server reconciliation, and buffered interpolation for other explorers. A short grace period after leaving an edge and a buffered jump press before landing make platforming more forgiving. Sprint energy recovers while resting; meals restore it faster.

## Build, explore, and settle in

Gather cedar and fiber, mine stone with your cedar pick, and craft a stone pick near a workbench. Better tools open iron veins, lumen crystals, and other resources. Stage 2 adds copper, clay, basalt, limestone, granite, amber, amethyst, and fishing pearls alongside the original materials.

The **177-item catalogue** includes masonry, colored planks and glass, ceramic tiles, metal construction, furniture, rugs, garden decorations, lamps, fountains, and nine wearable hats, backpacks, and outfits. Crafting search and categories help find recipes and required stations. Equipment changes your explorer's appearance and persists across sessions.

New worlds are **256 × 80 tiles** with three seeded biomes, additional deposits, and shallow fishing ponds. Older worlds retain their **144 × 56** terrain. Creating a world immediately adds it to everyone's catalogue. Search by name or founder, filter by biome, sort by online explorers or newest worlds, and keep personal favorites. Place a **World Core** to claim a world; owners can permit guests or appoint builders. NEXUS remains an unclaimed shared refuge.

Plant grain, carrot, tomato, or berry seeds on earth. Crops grow by real timestamps, including time offline: **90 seconds for grain, 100 for carrots, 120 for tomatoes, and 150 for berries**. Press **E** at a ripe crop to harvest.

Place a furnace, potter kiln, weaver loom, cooking hearth, or crystal workshop, then press **E** to choose a recipe. Timed jobs consume ingredients up front and remain saved while you explore, sign out, or restart the server. Return to collect the output when ready. Only the explorer who queued a job can collect it; a full backpack leaves the job available. A station with outstanding jobs cannot be mined. Instant recipes remain available at their matching station.

Craft a **Willow fishing rod**, select it on the hotbar, point at nearby open water, and press **G** or **E**. A catch costs ten energy; the server enforces a three-second cooldown and awards a trout or occasional pearl. Cook food for longer expeditions. Craft a **Wayfarer portal**, place it where you can build, and press **E** to link an existing world. Later interactions travel to that world's safe spawn.

Build spring platforms for automatic launch jumps, then use the **K** minimap to get your bearings across a larger world. Colored lights, flowing water, animated fountains, and portal effects give new homes more movement and atmosphere.

The journal contains six milestones for building, mining, farming, crafting, world discovery, and fishing. Progress and reward claims are saved by the server. Collect each reward once when its goal is complete. Wave, cheer, send a heart, dance, or sit through the emote panel; nearby explorers see the animation.

## Play together

**P** opens the social panel. Send a friend request by explorer name; accepted friendships persist across reconnects. See whether friends are online and which world they are visiting, send a private message, join their world, or invite them to yours. Private messages require both players online. Blocks persist and prevent contact; requests, messages, invitations, and trades respect them. Messages and invitations are temporary rather than an offline mailbox.

Players share one authority server. On the same computer, open another browser tab and use another account. Across computers, use the host-and-join instructions above. The browser initially connects to the server that served its page, and HTTPS pages require WSS. A remembered session for another server does not silently redirect this page. The menu identifies the selected server; accounts and progress belong to that server.

Two nearby explorers can trade exact item offers: request → accept → edit → both lock → both confirm. Editing clears locks and confirmations. Inventory changes and pickups pause during a trade. Closing it, travelling, disconnecting, blocking the partner, or leaving range cancels safely. Both inventories commit together; the server validates quantities, capacity, and the current trade ID.

## Administration

Press **Enter**, type **`/addomen`**, and press **Enter** again. The menu includes a searchable item catalogue, grants to yourself or another explorer, an account directory, kicks, permanent bans and unbans, timed mutes and unmutes, and safe world travel. The server checks every action and records an audit entry. Typing the command as a regular explorer does not grant access.

On the default local `127.0.0.1` server, the oldest existing account becomes administrator when none has been configured; with a new save, the first account created becomes administrator. Administrators cannot kick, ban, or mute themselves or another administrator through the menu.

For a fresh Wi-Fi save, open **Play-WORLDFORGE.bat** first, create your own account, then stop that launcher with **Ctrl+C** and open **Host-WORLDFORGE-LAN.bat** from the same folder. Your existing administrator role stays saved when friends join. If you copy your previous `data` folder during an update, its roles also remain intact.

Choose administrators explicitly with `py scripts/play.py --admin YourExplorerName` on Windows or `python -m server.main --admin YourExplorerName`. Repeat `--admin` for additional names. LAN/public listeners and explicit `--public` mode do not appoint the first visitor automatically, including behind a tunnel to localhost. Create and secure the intended account locally before exposing a named administrator publicly. Roles and moderation persist across restarts.

## Development and validation

```sh
bash scripts/setup.sh
bash scripts/serve.sh
# In another terminal, launch the native client:
bash scripts/godot.sh
```

Open `project.godot` in Godot for editing. `shared/definitions.json` is the stable-ID item, recipe, and movement registry. A source checkout requires Godot to rebuild the browser client. On a fresh machine, `python3 scripts/install_templates.py` installs official Web templates after verifying their SHA512 checksum; `bash scripts/export_web.sh` refreshes `build/web`.

```sh
.venv/bin/python -m unittest discover -v
bash scripts/check_client.sh
bash scripts/export_web.sh
# Optional exported-client browser checks; require Playwright and Chromium:
python3 tests/browser_smoke.py
python3 tests/visual_smoke.py
python3 tests/session_browser.py
python3 tests/stage2_browser.py
python3 tests/reconnect_browser.py
# Acceptance against an already running shared host (creates two QA accounts/world):
python3 tests/hosted_browser.py --url https://YOUR_GAME_DOMAIN
# Explicit LAN-only test; this does not prove internet reachability:
python3 scripts/join_lan.py --server http://YOUR_HOST_LAN_ADDRESS:8765 --no-browser
python3 tests/hosted_browser.py --url http://YOUR_HOST_LAN_ADDRESS:8765 --allow-lan \
  --web-client-url 'http://127.0.0.1:8770/?join=ws%3A%2F%2FYOUR_HOST_LAN_ADDRESS%3A8765'
```

See [docs/validation.md](docs/validation.md) for executed checks and [docs/architecture.md](docs/architecture.md) for authority and persistence boundaries. Saves are in ignored `data/worldforge.sqlite3`; use SQLite's backup API for a live-server backup. Generated `.godot`, `.tools`, `.venv`, and `build` folders are local setup outputs. The playable ZIP excludes personal saves and credentials.

SQLite mutations run in one authority process, and the catalogue has a 100-world development cap. Worlds use a full entry snapshot and subsequent world-scoped deltas. Chunk streaming, measured large-player capacity, distributed hosting, guilds, combat, bosses, shops, and a marketplace remain future development. The larger download budget is available for useful content; this release adds no filler files to reach it.
